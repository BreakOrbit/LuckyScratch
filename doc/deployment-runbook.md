# LuckyScratch Deployment Runbook

This runbook covers the current local development path and the production-style live deployment path for LuckyScratch.

## Scope And Assumptions

- The repository is the Hardhat flavor of Scaffold-ETH 2.
- Live contract deployment is currently configured for `sepolia` and `mainnet`.
- Backend API and worker require PostgreSQL, an EVM RPC endpoint, and active LuckyScratch deployment metadata.
- Final user actions remain wallet-submitted. The backend indexes, validates, proxies reveal requests, and serves read models.
- Current local caveat: the active deploy script is not a complete localhost deploy script. It expects real configured cUSDC and Chainlink VRF settings for supported live networks. Local contract behavior is tested through Hardhat fixtures, not through `yarn deploy --network localhost`.

## Local Development Runbook

### 1. Install Dependencies

```bash
corepack enable
yarn install
```

### 2. Validate Contracts, Backend, And Frontend

```bash
yarn compile
yarn hardhat:check-types
yarn hardhat:test

cd packages/backend
go test ./...

cd ../..
yarn next:check-types
yarn next:build
```

Expected result:

- Hardhat tests pass against the fhEVM mock environment.
- Backend Go tests pass without requiring a live database.
- Next.js type check and production build succeed.

### 3. Start Local PostgreSQL

Use an existing PostgreSQL instance, or start a disposable one:

```bash
docker run --name lucky-scratch-postgres \
  -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=lucky_scratch \
  -p 5432:5432 \
  -d postgres:16
```

If the container already exists:

```bash
docker start lucky-scratch-postgres
```

### 4. Prepare Backend Environment

```bash
cd packages/backend
cp .env.example .env
```

For a local backend, the default template values are generally:

```bash
DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/lucky_scratch?sslmode=disable
RPC_URL=http://127.0.0.1:8545
CHAIN_ID=31337
CHAIN_NAME=hardhat
API_PUBLIC_BASE_URL=http://127.0.0.1:8080
CORS_ALLOWED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
```

Important: backend startup imports artifacts from `packages/hardhat/deployments/<CHAIN_NAME>/`. With the current deploy script, a complete localhost LuckyScratch artifact set is not generated by the normal deploy command. Keep this in mind before starting the API/worker locally.

### 5. Start A Local Chain

```bash
yarn chain
```

This starts the Hardhat node. It does not by itself deploy LuckyScratch.

### 6. Run The Backend When Deployment Artifacts Exist

Run this only after the configured chain has valid LuckyScratch deployment artifacts and matching onchain contracts:

```bash
cd packages/backend
set -a
source .env
set +a
go run .
```

Alternative split process mode:

```bash
go run . api
go run . worker
```

Backend health check:

```bash
curl http://127.0.0.1:8080/healthz
```

### 7. Run The Frontend

```bash
cd packages/nextjs
cp .env.example .env.local
```

Set local API values:

```bash
NEXT_PUBLIC_BACKEND_URL=http://127.0.0.1:8080
NEXT_PUBLIC_IPFS_GATEWAY_BASE_URL=
NEXT_PUBLIC_SEPOLIA_RPC_URL=
```

Start the app:

```bash
cd ../..
yarn start
```

Open `http://localhost:3000`.

### 8. Reset Local Backend Data

Stop the backend API and worker before cleanup:

```bash
cd packages/backend
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f sql/clean_database.sql
```

Restart the backend afterwards so migrations, deployment import, and indexing rebuild from the current artifacts.

## Production Deployment Runbook

The current production-style path is Sepolia-first. Mainnet uses the same shape but has stricter redeploy safeguards.

### 1. Prepare Hardhat Environment

```bash
cd packages/hardhat
cp .env.example .env
```

Set or generate the deployer:

```bash
yarn account:import
```

Required or recommended live deploy values:

```bash
ALCHEMY_API_KEY=...
ETHERSCAN_V2_API_KEY=...
DEPLOYER_PRIVATE_KEY_ENCRYPTED=...
CHAINLINK_VRF_SUBSCRIPTION_ID_SEPOLIA=...
```

Optional Chainlink overrides:

```bash
CHAINLINK_VRF_COORDINATOR=...
CHAINLINK_VRF_KEY_HASH=...
CHAINLINK_VRF_CALLBACK_GAS_LIMIT=1500000
CHAINLINK_VRF_REQUEST_CONFIRMATIONS=3
CHAINLINK_VRF_NATIVE_PAYMENT=true
```

The deploy script already contains the current configured cUSDC address and default Chainlink VRF v2.5 settings for supported networks.

### 2. Deploy Contracts

From the repository root:

```bash
yarn deploy --network sepolia
```

Fresh redeploy is the default. It deletes local deployment records for the LuckyScratch contract set before deploying new addresses.

To intentionally keep existing deployments:

```bash
LUCKY_SCRATCH_REUSE_EXISTING=true yarn deploy --network sepolia
```

Mainnet fresh redeploy requires an explicit confirmation:

```bash
LUCKY_SCRATCH_FORCE_MAINNET_REDEPLOY=true yarn deploy --network mainnet
```

After deployment, record the printed `LuckyScratchVRFAdapter` address and add it as a consumer on the configured Chainlink VRF subscription. Pool creation will fail until this is done.

### 3. Verify Contracts

```bash
yarn verify --network sepolia
```

### 4. Prepare Backend Production Environment

Use a real PostgreSQL database. For Docker-based backend deployment:

```bash
cd packages/backend
cp .env.docker.example .env.docker
```

Minimum Sepolia backend values:

```bash
DATABASE_URL=postgres://app_user:strong-password@db.example.com:5432/lucky_scratch?sslmode=require
RPC_URL=https://eth-sepolia.g.alchemy.com/v2/your-key
CHAIN_ID=11155111
CHAIN_NAME=sepolia
API_PUBLIC_BASE_URL=https://api.example.com
CORS_ALLOW_ALL_ORIGINS=false
CORS_ALLOWED_ORIGINS=https://app.example.com
ADMIN_TOKEN=replace-with-a-long-random-token
AUTO_MIGRATE=true
AUTO_IMPORT_DEPLOYMENTS=true
```

Pool artwork and metadata uploads require IPFS config:

```bash
IPFS_PROVIDER=pinata
IPFS_PINATA_JWT=...
IPFS_GATEWAY_BASE_URL=https://gateway.pinata.cloud/ipfs
IPFS_PINATA_API_BASE_URL=https://api.pinata.cloud
```

For Sepolia, Zama relayer and protocol defaults are built into the backend when `CHAIN_ID=11155111`. Leave `ZAMA_*` overrides empty unless targeting a custom relayer or protocol deployment.

### 5. Start Or Refresh Backend Containers

```bash
cd packages/backend
./update-containers.sh --env-file .env.docker --logs
```

The compose stack starts:

- `backend-api`
- `backend-worker`

It mounts `packages/hardhat/deployments` read-only into the containers and imports deployment metadata on startup when `AUTO_IMPORT_DEPLOYMENTS=true`.

Health checks:

```bash
curl https://api.example.com/healthz
curl https://api.example.com/api/v1/pools
```

Admin check:

```bash
curl -H "Authorization: Bearer $ADMIN_TOKEN" https://api.example.com/api/v1/admin/jobs
```

### 6. Deploy Frontend

Prepare frontend env values in Vercel or the hosting platform:

```bash
NEXT_PUBLIC_BACKEND_URL=https://api.example.com
NEXT_PUBLIC_IPFS_GATEWAY_BASE_URL=https://gateway.pinata.cloud/ipfs
NEXT_PUBLIC_SEPOLIA_RPC_URL=https://eth-sepolia.g.alchemy.com/v2/your-key
NEXT_PUBLIC_ALCHEMY_API_KEY=...
NEXT_PUBLIC_WALLET_CONNECT_PROJECT_ID=...
```

Validate locally before deployment:

```bash
yarn next:build
```

Deploy with the repo script:

```bash
yarn vercel:yolo --prod
```

### 7. Post-Deploy Smoke Test

Check these paths from a browser:

- `/`
- `/store`
- `/create-pool`
- `/my-tickets`
- `/profile`

Check backend state:

```bash
curl https://api.example.com/healthz
curl https://api.example.com/api/v1/stats/overview
curl https://api.example.com/api/v1/pools
curl -H "Authorization: Bearer $ADMIN_TOKEN" https://api.example.com/api/v1/admin/jobs
```

Product smoke flow:

1. Confirm wallet can connect on Sepolia.
2. Confirm faucet page can show cUSDC metadata and wallet confidential balance flow.
3. Create or inspect an active pool.
4. Confirm purchase-context loads for a pool.
5. Confirm backend worker lag in admin jobs is acceptable.

## Fresh Redeploy Procedure

Use this when deploying a new LuckyScratch contract set.

1. Stop backend API and worker.
2. Deploy contracts with `yarn deploy --network sepolia`.
3. Add the new `LuckyScratchVRFAdapter` address as a Chainlink VRF subscription consumer.
4. If old indexed IDs would collide with the fresh contracts, clean the backend database:

```bash
cd packages/backend
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f sql/clean_database.sql
```

5. Restart backend API and worker.
6. Confirm deployment import, migrations, and indexer catch-up through `/healthz` and `/api/v1/admin/jobs`.
7. Rebuild and redeploy the frontend if `packages/nextjs/contracts/deployedContracts.ts` or public env values changed.

## Reuse Existing Contracts

Use this when refreshing backend/frontend code without changing contract addresses:

```bash
LUCKY_SCRATCH_REUSE_EXISTING=true yarn deploy --network sepolia
```

Do not clean the database unless the indexed chain state is intentionally being reset.

## Operational Notes

- Keep `ZAMA_API_KEY` server-side only. Never expose it through `NEXT_PUBLIC_*`.
- `API_PUBLIC_BASE_URL` must be stable and publicly reachable when reveal-auth needs to emit ticket-scoped Zama proxy URLs.
- `CORS_ALLOWED_ORIGINS` must include the deployed frontend origin unless `CORS_ALLOW_ALL_ORIGINS=true` is intentionally enabled.
- `packages/nextjs/contracts/deployedContracts.ts` is generated from deployment artifacts and can be empty before a supported live deployment is written.
- Backend recurring jobs use PostgreSQL locks, not Redis.
- If a backend crash happens after an upstream Zama decrypt POST succeeds but before the upstream job id is persisted, the pinned relayer flow cannot fully recover that narrow case because the upstream API has no client-provided idempotency key.
